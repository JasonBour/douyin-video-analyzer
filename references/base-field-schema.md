# 飞书多维表格字段 Schema（PREP）

本文件定义抖音视频拆解库的标准字段结构，用于创建飞书 Base 时的 `--fields` 参数，以及写入数据时的字段映射参考。

## 标准字段列表（按顺序）

| 序号 | 字段名 | 字段类型 | 说明 |
|---|---|---|---|
| 1 | 视频链接 | 文本(text) | 视频原始页面链接 |
| 2 | 视频标题 | 文本(text) | 视频标题/首行文案 |
| 3 | 内容结构 | 多行文本(text) | PREP 完整结构（P 观点/R 理由/E 展开/P 结尾总结），直接可照讲；仅并列多点理由用 1、2、3 编号，连续一段话不编号 |
| 4 | 观点(Point) | 多行文本(text) | 【核心内容】原文精简版 + 【原文】 |
| 5 | 理由(Reason) | 多行文本(text) | 【核心内容】原文精简版 + 【原文】 |
| 6 | 例子(Example) | 多行文本(text) | 【核心内容】原文精简版 + 【原文】 |
| 7 | 总结(Point) | 多行文本(text) | 【核心内容】原文精简版 + 【原文】 |
| 8 | 原文稿 | 多行文本(text) | 视频完整逐字稿（不删减、不改写） |

> 字段顺序固定：视频链接 → 视频标题 → 内容结构 → 观点(Point) → 理由(Reason) → 例子(Example) → 总结(Point) → 原文稿。

## 创建 Base 时的 fields JSON

使用 `lark-cli base +table-create --fields '<json>'` 时，传入以下 JSON 数组（注意第一条是主字段）：

```json
[
  {"name": "视频链接", "type": "text"},
  {"name": "视频标题", "type": "text"},
  {"name": "内容结构", "type": "text"},
  {"name": "观点(Point)", "type": "text"},
  {"name": "理由(Reason)", "type": "text"},
  {"name": "例子(Example)", "type": "text"},
  {"name": "总结(Point)", "type": "text"},
  {"name": "原文稿", "type": "text"}
]
```

## 字段内容规范

### 内容结构字段（PREP 完整结构）

```
P 观点：<一句话核心观点，直接可讲>

R 为什么这么说：<支撑理由，直接给内容本身>
1. <理由1>
2. <理由2>
3. <理由3>

E 展开讲讲：<展开/案例/方法的实质内容，可照讲>

P 结尾总结：<结尾总结，可照讲>
```

**硬性要求**：
- 所有内容**直接可照讲**，禁止写对博主行为的描述（如"他直接给出结论""她强调说""博主在叮嘱"）。
- **仅当理由确实是并列的多点时，才用 1、2、3 编号**；如果 R 是一两句连续的话（递进/转折/论证一段话），直接写一段，不要强行拆编号。
- **允许缺段，禁止凑数**：PREP 是拆解工具不是强制模板，某段（尤其 E 展开/R 理由）没有实质内容时，如实标注"（本视频为XX型内容，无独立展开/案例部分）"，绝不能为了填满 PREP 把其他段落内容重复搬进来。R 是"为什么这么说"的论据、E 是"展开讲讲"的案例/方法/数据，二者必须互不重复。

### PREP 四字段（观点/理由/例子/总结）

每字段两段式，换行分隔：

```
【核心内容】<原文精简版，保留原话表达，只做必要删减>
【原文】"<摘自逐字稿的原话，可省略中间用……连接>"
```

**硬性要求**：
- 【核心内容】尽量按照原文的语言表达，是原文的精简版，不要大改。
- 【原文】必须来自逐字稿原话，不编造。

## 已有 Base 字段对齐

当用户提供已有 Base 时，先执行 `+field-list` 获取现有字段，然后：

1. **字段名完全匹配**：直接映射写入。
2. **字段名不同但语义相同**：建立映射关系，按用户字段名写入。
3. **缺少必要字段**：用 `+field-create` 补建缺失字段，参考上面的字段定义。
4. **字段类型不匹配**：按实际类型写入，并提醒用户。

不要强行修改用户已有字段的名称或类型，只在缺失时补建。
